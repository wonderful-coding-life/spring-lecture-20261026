# PRD.md

## 1. 프로젝트 목표

회원가입과 로그인을 지원하고, 회원이 게시글을 작성하고 관리할 수 있는 Spring Boot 웹 게시판을 구현한다.

주요 기능은 다음과 같다.

- 회원가입, 로그인, 로그아웃
- 게시글 목록, 상세, 등록, 수정, 삭제
- 게시글 페이징
- 입력값 검증 및 작성자 권한 검사

## 2. 사용자 권한

| 기능 | 비로그인 | 로그인 |
|---|---|---|
| 회원가입, 로그인 | O | O |
| 게시글 목록 및 상세 조회 | O | O |
| 게시글 등록 | X | O |
| 게시글 수정 및 삭제 | X | 본인 글만 |
| 로그아웃 | X | O |

인증은 Spring Security의 세션 기반 Form Login을 사용한다.

## 3. 데이터 모델

### Member

| 필드 | 조건 |
|---|---|
| id | 기본키, 자동 증가 |
| username | 필수, 고유, 4~20자 |
| password | 필수, BCrypt 암호화 |
| name | 필수 |
| email | 필수, 고유, 이메일 형식 |

비밀번호는 입력 시 8자 이상이어야 한다.

### Article

| 필드 | 조건 |
|---|---|
| id | 기본키, 자동 증가 |
| title | 필수, 100자 이하 |
| content | 필수 |
| createdAt | 작성 시각 자동 설정 |
| author | Member와 다대일 단방향 관계 |

## 4. 데이터베이스

- 기본 데이터베이스는 MariaDB를 사용한다.
- `support/schema.sql`에 MariaDB 테이블 생성 SQL을 작성한다.
- 스키마는 수동으로 생성하며 애플리케이션에서 자동 실행하지 않는다.
- Entity 매핑은 `schema.sql`과 일치해야 한다.
- 접속 정보는 `application.properties`에서 환경 변수 `DB_URL`, `DB_USER`, `DB_PASS`를 사용한다.
- 테스트는 H2 인메모리 데이터베이스를 사용한다.
- `src/test/resources/application.properties`에 테스트 설정을 작성한다.
- 별도의 MariaDB 없이 `./gradlew test`가 실행되어야 한다.

## 5. 기능 요구사항

### 5.1 회원가입

URL:
- `GET /members/new`: 회원가입 화면
- `POST /members`: 회원가입 처리

입력 항목:
- 로그인 아이디, 비밀번호, 비밀번호 확인, 이름, 이메일

처리 조건:
- 모든 항목은 필수이며 데이터 모델의 입력 조건을 따른다.
- 비밀번호 확인 값이 일치해야 한다.
- 로그인 아이디와 이메일은 중복될 수 없다.
- 입력 오류는 해당 화면에 메시지로 표시한다.
- 가입 성공 시 `/login`으로 이동한다.

### 5.2 로그인 및 로그아웃

URL:
- `GET /login`: 로그인 화면
- `POST /login`: 로그인 처리
- `POST /logout`: 로그아웃

처리 조건:
- 로그인 아이디와 비밀번호로 인증한다.
- `UserDetailsService`를 구현하여 회원 정보를 조회한다.
- 로그인 성공 시 `/articles`로 이동한다.
- 로그아웃 성공 시 `/login`으로 이동한다.

### 5.3 게시글 목록

URL:
- `GET /articles`

처리 조건:
- 한 페이지에 10개씩 표시한다.
- 작성일 기준 최신순으로 정렬한다.
- 게시글 번호, 제목, 작성자, 작성일을 표시한다.
- 제목을 클릭하면 상세 화면으로 이동한다.
- 이전, 다음, 페이지 번호를 제공하고 현재 페이지를 강조한다.
- 게시글이 없으면 "등록된 게시글이 없습니다."를 표시한다.

### 5.4 게시글 상세

URL:
- `GET /articles/{articleId}`

처리 조건:
- 제목, 작성자, 작성일, 내용을 표시한다.
- 내용의 줄바꿈을 유지한다.
- 목록으로 돌아가는 버튼을 제공한다.
- 작성자에게만 수정 및 삭제 버튼을 표시한다.

### 5.5 게시글 등록

URL:
- `GET /articles/new`: 등록 화면
- `POST /articles`: 등록 처리

처리 조건:
- 제목과 내용을 입력받고 필수값을 검증한다.
- 작성자는 현재 로그인한 회원으로 설정한다.
- 입력 오류는 등록 화면에 표시한다.
- 등록 성공 시 `/articles`로 이동한다.

### 5.6 게시글 수정

URL:
- `GET /articles/{articleId}/edit`: 수정 화면
- `POST /articles/{articleId}/edit`: 수정 처리

처리 조건:
- 기존 제목과 내용을 수정 화면에 표시한다.
- 작성자만 수정할 수 있다.
- 입력값은 등록과 동일하게 검증한다.
- 수정 성공 시 해당 게시글 상세 화면으로 이동한다.

### 5.7 게시글 삭제

URL:
- `POST /articles/{articleId}/delete`

처리 조건:
- 작성자만 삭제할 수 있다.
- JavaScript `confirm()`으로 삭제를 확인한다.
- 삭제 성공 시 `/articles`로 이동한다.

## 6. 보안 및 오류 처리

- 회원가입, 로그인, 게시글 조회는 인증 없이 접근할 수 있다.
- 게시글 등록, 수정, 삭제는 로그인이 필요하다.
- 게시글 수정 및 삭제 권한은 Service에서 검사한다.
- CSRF 보호는 유지한다.
- 존재하지 않는 데이터와 권한 위반은 일관되게 예외 처리한다.
- 입력값 검증 오류는 해당 화면의 입력 항목 아래에 표시한다.

## 7. 화면 구성

다음 Thymeleaf 템플릿을 작성한다.

```text
templates/
├── login.html
├── members/
│   └── create.html
└── articles/
    ├── list.html
    ├── detail.html
    └── form.html
```

- `/` 요청은 `/articles`로 리다이렉트한다.
- `articles/form.html`은 등록과 수정에서 공통으로 사용한다.
- 상단에 게시판 제목과 로그인 상태에 따른 메뉴를 표시한다.
- 비로그인 상태에서는 로그인과 회원가입 메뉴를 표시한다.
- 로그인 상태에서는 로그인 아이디, 글쓰기, 로그아웃 메뉴를 표시한다.
- Tailwind CSS를 사용하여 깔끔하고 반응형인 화면을 구현한다.
- 콘텐츠는 중앙 정렬하고 카드, 버튼, 입력 필드를 일관된 스타일로 작성한다.

## 8. 단계별 구현 및 리뷰

다음 순서로 한 단계씩 구현한다.

| 단계 | 구현 내용 |
|---|---|
| 1 | Entity 및 `schema.sql` |
| 2 | Repository |
| 3 | Form 및 Validation |
| 4 | Service |
| 5 | Spring Security |
| 6 | Controller |
| 7 | Thymeleaf 화면 |
| 8 | 권한 및 예외 처리, 통합 테스트 |

### 진행 규칙

- 한 번에 하나의 단계만 구현한다.
- 현재 단계에 필요한 코드만 작성하고 다음 단계의 코드는 미리 구현하지 않는다.
- 단계별 구현 중에는 애플리케이션이 완전히 실행되지 않아도 된다.
- 단계 구현 후 변경된 파일과 리뷰할 핵심 코드를 보고하고 작업을 중단한다.
- 개발자가 리뷰하여 수정 또는 승인을 요청한다.
- 리뷰 승인이 완료된 후에만 다음 단계로 진행한다.
- 마지막 단계에서 전체 기능과 테스트를 확인한다.

### 진행 상태 관리

프로젝트 루트의 `progress.json`을 사용한다.

| status | 의미 |
|---|---|
| `pending` | 아직 시작하지 않은 단계 |
| `in_progress` | 구현 중이거나 리뷰 대기 중인 단계 |
| `done` | 개발자가 리뷰 후 승인한 단계 |

- 단계 시작 시 `in_progress`로 변경한다.
- 코드 구현이 끝나도 리뷰 승인 전까지 `in_progress`를 유지한다.
- 개발자가 승인하면 `done`으로 변경한다.
- `done`으로 변경한 후 다음 단계를 진행할 수 있다.

진행 상태 관리의 세부 규칙은 `AGENTS.md`를 따른다.
